| 目的 | HTTP API のパス、本体、状態コードを定める |

この資料は、API の仕様です。資料の入口は「ドキュメント一覧」です。何を作るかの正は「要件定義書」です。言葉の意味は「用語定義書」に従います。表の項目は「データベース設計」です。言語とフレームワークの正は「技術スタック」です。

バックエンドの言語は JavaScript です。フレームワークは Hono です。Hono は Cloudflare Workers の上で動きます。Workers は実行環境であり、言語でもフレームワークでもありません。データベースは SQLite です。SQL で読み書きします。SQLite の置き場所は、Durable Object のストレージです。Durable Object はデータベース製品ではありません。

画面の HTML は、Workers の静的配信が渡します。この資料の API は、パスが `/api/` で始まるものだけです。

ベース URL は、手元では `http://127.0.0.1:8787` です。本体は JSON です。文字コードは UTF-8 です。ログイン後の呼び出しは、Cookie `session` を送ります。

---

## 1. 共通

| 項目 | 内容 |
|---|---|
| フレームワーク | Hono 4.13 |
| 言語 | JavaScript |
| データベース | SQLite |
| 成功時の本体 | JSON。ログアウトだけ本体なし |
| 失敗時の本体 | `{ "error": "..." }` |
| 認証 | Cookie `session`。HttpOnly、SameSite=Lax、Path=/、有効期限は7日。値は64文字の16進数。パスワードは返さない |

| error | 意味 | 状態コード |
|---|---|---|
| invalid | 名前、パスワード、または風車の値が約束に合わない | 400 |
| unauthorized | ログインしていない、または名前とパスワードが一致しない | 401 |
| taken | その名前はすでに使われている | 409 |
| method | そのパスにあるメソッドではない | 405 |
| not_found | 定義していないパス | 404 |

名前は、英数字、`_`、`-` の1文字以上32文字以下です。パスワードは8文字以上64文字以下です。パスワードは平文で残しません。PBKDF2-SHA-256、反復10万回でハッシュし、ソルトと一緒に SQLite の `users` へ書きます。

風車の値は、次だけを受けます。

| 項目 | 約束 |
|---|---|
| angle | 有限の数。絶対値は 10000000 以下 |
| omega | `0`、`0.36`、`-0.36` のいずれか。時計回りは `0.36`、逆回転は `-0.36`、停止は `0` |
| speed | `1` または `2` |

ログインしていない呼び出しは、その人の行を読みません。アカウントごとに `pinwheel` は1行です。

## 2. 一覧

| メソッド | パス | 認証 | 機能 |
|---|---|---|---|
| POST | `/api/register` | 不要 | A-1 登録し、その場でログインする |
| POST | `/api/login` | 不要 | A-2 ログインする |
| POST | `/api/logout` | 任意 | A-3 ログアウトする。Cookie が無くても成功にする |
| GET | `/api/me` | 要 | ログイン中の名前を返す |
| GET | `/api/state` | 要 | その人の風車を読む |
| PUT | `/api/state` | 要 | その人の風車を書く |

---

## 3. POST /api/register

アカウントを作り、`pinwheel` に初期の1行を入れ、セッションを発行します。

リクエスト

```json
{ "name": "nsb", "password": "kazaguruma" }
```

成功は 201 です。

```json
{ "name": "nsb" }
```

応答には `Set-Cookie: session=...` が付きます。初期の風車は、角度 `-15`、角速度 `0`、倍率 `1` です。

| 状態 | 条件 |
|---|---|
| 201 | 登録できた |
| 400 | 名前またはパスワードが約束に合わない |
| 409 | 同じ名前がある |
| 405 | POST 以外 |

---

## 4. POST /api/login

名前とパスワードが一致したら、セッションを発行します。

リクエストは登録と同じ形です。成功は 200 で、本体は `{ "name": "nsb" }` です。`Set-Cookie` が付きます。

| 状態 | 条件 |
|---|---|
| 200 | 一致した |
| 400 | 名前またはパスワードが約束に合わない |
| 401 | 名前が無い、またはパスワードが違う |
| 405 | POST 以外 |

---

## 5. POST /api/logout

セッションの行を消し、Cookie を消します。成功は 204 で、本体はありません。ログインしていなくても 204 です。

| 状態 | 条件 |
|---|---|
| 204 | Cookie を消した |
| 405 | POST 以外 |

---

## 6. GET /api/me

ログイン中の名前を返します。

```json
{ "name": "nsb" }
```

| 状態 | 条件 |
|---|---|
| 200 | セッションが有効 |
| 401 | セッションが無い、または期限切れ |
| 405 | GET 以外 |

---

## 7. GET /api/state

ログイン中の人の風車を返します。

```json
{ "angle": -15, "omega": 0, "speed": 1 }
```

| 状態 | 条件 |
|---|---|
| 200 | その人の行を返した |
| 401 | ログインしていない |
| 405 | GET と PUT 以外 |

---

## 8. PUT /api/state

ログイン中の人の行だけを更新します。他のアカウントの行は変えません。

リクエスト

```json
{ "angle": -15, "omega": 0.36, "speed": 2 }
```

成功は 200 で、書いたあとの行を返します。形は GET と同じです。

| 状態 | 条件 |
|---|---|
| 200 | その人の行を更新した |
| 400 | 値が約束に合わない。本体が JSON でない |
| 401 | ログインしていない |
| 405 | GET と PUT 以外 |
